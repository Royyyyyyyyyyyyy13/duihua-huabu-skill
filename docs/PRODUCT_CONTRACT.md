# 对话画布 2.0 产品契约

## 初心

长对话的真正问题不是消息数量，而是阶段、决定、结果和当前方向散落在聊天流里。对话画布把这些阶段性信息变成一张可回看、可定位、可重新组装的工作地图。

## 核心任务

用户打开当前对话的画布后，应当在很短时间内回答四个问题：

1. 这次对话经历了哪些关键阶段？
2. 当前正在推进什么？
3. 某个决定、实现或验证结果在哪里？
4. 下一次继续讨论时，需要带回哪些压缩上下文？

## 不可破坏的边界

- 每个 Codex 对话使用独立 session。
- 节点代表小话题或小阶段，不代表每一句消息。
- checkpoint 内容由当前对话里的 Codex 在阶段完成时生成。
- 画布不修改 Codex 记忆、系统上下文或内部推理。
- 画布不控制 Codex 客户端输入框，也不自动发送消息。
- 节点内容属于对话记录，默认不可删除；布局、连线和组装顺序可以修改。
- 原文只作为证据，结构化详情和压缩上下文承担主要阅读与复用任务。

## 2.0 交互语义

- 实线：正式 checkpoint 之间的阶段关系，方向为“前置阶段 -> 后续阶段”。
- 虚线：正式 checkpoint 到“当前讨论中”的活跃来源。点击节点不会改变虚线。
- 主线组装：按实线关系实时计算输入顺序。
- 手动组装：只使用用户加入的节点及顺序。
- 还原画布：只恢复默认布局、正式连线和讨论中来源，不删除节点。
- 撤销/重做：覆盖节点移动、讨论中移动、连线新增/删除/重连和画布还原，最多保留 40 步。

## 2.0 质量标准

- 长画布可搜索、筛选、缩放、平移、框选、定位和总览。
- 新 checkpoint 到达时不打断输入框编辑，不覆盖用户当前操作。
- 并发写入不能丢节点、连线或布局。
- schema 升级先备份，再迁移；旧 session 的节点、连线、位置和组装顺序必须保留。
- 节点缺少详情或压缩上下文时，数据层生成明确的摘要兜底，不出现空白详情。
- 首次启用旧对话时，优先由当前 Codex 根据已有上下文生成自适应数量的回溯节点；本机记录扫描只作为明确触发的兜底。
- 页面无需联网，运行时只依赖 Python 本地服务和已经打包的静态资源。
